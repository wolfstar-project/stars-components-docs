## Description

Discord evaluates regular expressions, for example in AutoMod keyword filters, with the [Rust `regex` crate](https://docs.rs/regex). Its syntax is close to JavaScript's but not the same: it has no lookarounds or backreferences, `\d`, `\w` and `\b` are Unicode-aware, flags are inline, and character classes support set operations. You cannot pass an AutoMod pattern to `RegExp` as it is.

`@wolfstar/rust-regex` parses a Rust pattern and returns the source and flags of a JavaScript `RegExp` that matches the same text. Use it to preview and test AutoMod patterns in your bot before you send them to Discord. The package has no dependencies.

## Features

- Parses the Rust syntax, so a pattern Rust rejects (a lookahead, a backreference, an unbalanced group) fails here too, with the position of the problem
- Unicode `\d`, `\w`, `\s` and `\b`, and `\p{...}` classes with Rust's loose names (`\p{Greek}`, `\p{uppercase_letter}`)
- Inline flags `(?i)`, `(?s)`, `(?m)`, `(?U)` and `(?x)`, global or scoped to a group
- Class set operations (`[a-z&&[^aeiou]]`, `[\p{L}--[a-z]]`, `[a-c~~b-d]`) and ASCII classes (`[[:alpha:]]`)
- Named groups in both Rust spellings, `(?P<name>...)` and `(?<name>...)`
- ESM only, Node.js 20 or newer

## Usage

`toRegExp` returns a compiled `RegExp`. `transpile` returns the `source` and `flags` separately, so you can store or log them.

```typescript
import { RustRegexError, toRegExp, transpile } from '@wolfstar/rust-regex';

// A ready to use RegExp
const regex = toRegExp(String.raw`(?i)\b(?:free\s+nitro|discord\.gift/\w+)\b`);
regex.test('Get FREE Nitro now'); // true

// Or the pieces, to store or log
transpile(String.raw`(?P<year>\d{4})-(?P<month>\d{2})`);
// { source: '(?<year>\\p{Nd}{4})-(?<month>\\p{Nd}{2})', flags: 'v', usesModifiers: false }

try {
	toRegExp('(?=lookahead)');
} catch (error) {
	if (error instanceof RustRegexError) {
		console.log(error.code); // 'unsupported_lookaround'
		console.log(error.position); // 0
	}
}
```

The result always uses the [`v` flag](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/RegExp/unicodeSets), plus `i` when the pattern is case-insensitive. To add flags such as `g`, pass them in the `extraFlags` option of `toRegExp`.

### Options

| Option       | Applies to              | Description                                                                                         |
| ------------ | ----------------------- | --------------------------------------------------------------------------------------------------- |
| `flags`      | `transpile`, `toRegExp` | Rust flags the pattern starts with, as if it began with `(?flags)`: any of `i`, `m`, `s`, `x`, `U`. |
| `validate`   | `transpile`             | Compiles the result to check that JavaScript accepts it. Defaults to `true`.                        |
| `extraFlags` | `toRegExp`              | JavaScript flags added to the ones the pattern needs: `d`, `g` or `y`. Any other flag throws.       |

`transpile` also returns `usesModifiers`. It is `true` when the source contains scoped case-insensitive groups such as `(?i:...)`, which need Node.js 23 or newer. See [Known differences from Rust](#known-differences-from-rust).

### Errors

Every failure throws a `RustRegexError`. It extends `SyntaxError` and carries a `code`, the `pattern` and the `position` of the problem. `position` is `undefined` when the problem is not at a place in the pattern, as for `invalid_option` and `invalid_output`.

| `code`                      | Meaning                                                                                                          |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `invalid_syntax`            | Rust would reject the pattern as well.                                                                           |
| `unsupported_lookaround`    | Lookahead or lookbehind. Rust does not have them, so Discord rejects the pattern.                                |
| `unsupported_backreference` | `\1`, `\k<name>` or `(?P=name)`. Rust does not have them either.                                                 |
| `unsupported_feature`       | Valid Rust that cannot be written as a JavaScript `RegExp`. See [What is not supported](#what-is-not-supported). |
| `invalid_output`            | The pattern is fine, but the JavaScript engine refuses the result, for example an unknown Unicode script name.   |
| `invalid_option`            | An option is wrong, for example an unknown Rust flag in `flags`, or `i` or `m` in `extraFlags`.                  |

Use `code` to tell a mistake in the Rust pattern (`invalid_syntax`, `unsupported_lookaround`, `unsupported_backreference`) from a limitation of the package (`unsupported_feature`, `invalid_output`).

## What is not supported

These are valid Rust and fail with `unsupported_feature`:

- `(?-u)` (ASCII and byte mode), `(?R)` (CRLF mode), the `\b{start}` family and `\<`, `\>`
- Unicode properties other than general category, script, script extensions and the binary ones
- Capture group names with `.`, `[` or `]`, which Rust allows and JavaScript does not

## Known differences from Rust

The transpiler is meant to preview and test patterns. Discord stays the source of truth for what a pattern matches. These differences are known:

- **No linear time guarantee.** Rust matches in time linear in the size of the text. A JavaScript `RegExp` backtracks, so a pattern such as `(a+)+$`, which is safe in Rust, can take exponential time on a long text. Do not run the result on text a stranger controls without a limit, for example in a worker with a timeout.
- **Scoped case-insensitivity needs ES2025.** `(?i)` at the start of the pattern becomes the `i` flag, which works everywhere. `(?i:...)`, `(?-i)` or a flag group in the middle becomes a regular expression modifier, and `transpile` reports `usesModifiers`. Modifiers need Node.js 23 or newer. Node.js 24 has an engine bug that lets a modifier group leak into the rest of the pattern in some cases.
- **Repeated groups that can match nothing.** For a pattern such as `(a?|b){1,2}`, JavaScript and Rust disagree about whether an empty iteration counts, so the overall match can differ in length.
- **Zero-width matches next to emoji.** V8 can report an empty match in the middle of a surrogate pair, for example `\B` on `x😀y`, where Rust only matches between characters.
- **Script names in `\p{...}`.** Script names are title-cased (`olditalic` becomes `Olditalic`) because the package has no table of script names. `transpile` fails with `invalid_output` for a spelling JavaScript does not know.
