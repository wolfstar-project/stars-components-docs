Changes to [`@wolfstar/plugin-broker`](https://github.com/wolfstar-project/plugins/tree/main/packages/plugin-broker). The plugin distributes gateway events across processes over Redis Streams, with consumer-group semantics and at-least-once delivery. For the weekly summary across all packages, see the [changelog overview](/documentation/changelog/index).

## `0.5.1`

### Updates

- **Dependencies** — Updated [`@wolfstar/plugin-cache`](/documentation/changelog/plugins/plugin-cache) to `0.7.0`.

## `0.5.0`

### New features

- **Module and plugin entry points** — Added `@wolfstar/plugin-broker/module` and `@wolfstar/plugin-broker/plugin`. List the module in `modules` in `stars.config`, or pass the `definePlugin` factory to `plugins`. Both need framework 6.1 (and `@wolfstar/kit` for the module); `./register` remains unchanged and still supports framework v3, v5 and v6. ([#192](https://github.com/wolfstar-project/plugins/pull/192))

### Updates

- **Dependencies** — Updated [`@wolfstar/plugin-cache`](/documentation/changelog/plugins/plugin-cache) to `0.6.0`.

## `0.4.0`

### New features

- **`replayGatewayDispatches`** — Replays the dispatches `forwardGatewayDispatches` publishes on a `GatewayClient` that never connects to Discord, so workers run `EventGatewayListener` pieces with the same Structures and previous state (`old` arguments) as the gateway process. Stream entries gain optional `state`, `shard` and `sequence` fields; `publish` takes them as `options`; and `BrokerMessage` exposes them. Entries without them, and consumers unaware of them, continue to work as before. ([#168](https://github.com/wolfstar-project/plugins/pull/168))

### Updates

- **Dependencies** — Updated [`@wolfstar/plugin-cache`](/documentation/changelog/plugins/plugin-cache) to `0.5.1`.

## `0.3.0`

### New features

- **Claim idle entries** — `claimIdle` claims (`XAUTOCLAIM`) entries that any consumer of the group left pending for too long, for example one that crashed and never restarted under the same name.
- **Dead-letter stream** — `maxDeliveries` moves an entry that keeps failing to a dead-letter stream instead of retrying it forever. Set the stream with `deadLetterStream` (`<stream>:dead` by default).
- **Graceful shutdown** — `shutdownSignals` stops the consumer on the given process signals. The consumer awaits the in-flight entry before letting the signal end the process.
- **`forwardGatewayDispatches`** — Publishes every dispatch a [`@wolfstar/plugin-gateway`](https://github.com/wolfstar-project/plugins/tree/main/packages/plugin-gateway) `GatewayClient` receives onto a broker, once it is written to the client's cache.

### Bug fixes

- **Pending entries drain** — A consumer could never drain its own pending entries: reading a consumer's history resolved to `null` once exhausted, and an entry that failed again was re-read forever, so the consumer never moved on to new entries. It now moves on.
- **Trimmed entries** — An entry trimmed from the stream while pending is now acknowledged instead of failing to decode.

## `0.2.0`

### New features

- **New package** — `@wolfstar/plugin-broker` distributes gateway events across processes over Redis Streams. `createBroker` publishes events (`XADD ... MAXLEN ~`). `ClientOptions.broker` configures a `BrokerConsumer`, started automatically once the client starts listening; the consumer reads events through a consumer group (`XGROUP CREATE ... MKSTREAM`, `XREADGROUP`, `XACK`) and redelivers a restarted consumer's own pending entries.
- **`BrokerListener` pieces** — Loaded from the `listeners` directory, like `EventGatewayListener` in `@wolfstar/plugin-gateway`. Listeners are typed per event through an augmentable `BrokerEvents` map. An entry is acknowledged only once every matching listener has resolved, so a throwing listener leaves its entry pending.
- **Pluggable payload codec** — Payloads are encoded with a `CacheCodec` from [`@wolfstar/plugin-cache`](/documentation/changelog/plugins/plugin-cache) (`jsonCodec()` by default).

### Updates

- **Dependencies** — Updated [`@wolfstar/plugin-cache`](/documentation/changelog/plugins/plugin-cache) to `0.4.0`.
