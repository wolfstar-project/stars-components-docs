Changes to [`@wolfstar/plugin-scheduled-tasks`](https://github.com/wolfstar-project/plugins/tree/main/packages/plugin-scheduled-tasks). The plugin adds scheduled tasks to `@wolfstar/http-framework`, run by a BullMQ worker. For the weekly summary across all packages, see the [changelog overview](/documentation/changelog/index).

## `0.4.1` (2026-11-06)

### Updates

- **Dependencies** — Updated third-party dependencies. ([#272](https://github.com/wolfstar-project/plugins/pull/272))

## `0.4.0` (2026-11-02)

### Updates

- **`@wolfstar/kit` 0.3 and `@wolfstar/schema` 0.12 peers** — The optional peer ranges now also accept `@wolfstar/kit` `^0.3.0` and `@wolfstar/schema` `^0.12.0`, next to the previous `^0.2.0` and `^0.9.0`. You can upgrade those packages without a peer dependency warning. ([#275](https://github.com/wolfstar-project/plugins/pull/275))

### Migration

- **Node.js 22 required** — The package now requires Node.js `>=22.0.0`. Node.js 20 is no longer supported. Upgrade Node.js before you update the package. ([#275](https://github.com/wolfstar-project/plugins/pull/275))

## `0.3.1` (2026-10-31)

### Updates

- **Dependencies** — Updated third-party dependencies. ([#240](https://github.com/wolfstar-project/plugins/pull/240))

## `0.3.0` (2026-10-20)

### New features

- **Own `stars.config` key** — The module sets `meta.configKey`, so you can write its options under the top-level `scheduledTasks` key of `stars.config` instead of the `[specifier, options]` tuple of `modules`. The tuple still works and is merged over the key. The key is typed in `defineConfig` once the module is imported in `stars.config.ts`. ([#259](https://github.com/wolfstar-project/plugins/pull/259))

### Updates

- **New optional peer** — `@wolfstar/schema` (`^0.9.0`) is a new optional peer that carries the `StarsConfig` type the keys extend.

### Migration

- **`@wolfstar/kit` peer raised** — The `@wolfstar/kit` peer range moves from `^0.1.0` to `^0.2.0`, the first version that reads `configKey`. If your project uses `@wolfstar/kit` 0.1, update it.

## `0.2.0`

### New features

- **Task readiness gate** — Adds a readiness gate for tasks that need the app to be up. Give the plugin a `ready` callback (with optional `readyTimeout` and `readyDelay`) and set `waitForReady: true` on the tasks that need it: when a job is taken before the app is ready it waits, and if the timeout passes it is moved back to `delayed` instead of failed, so it costs no attempt and emits no `scheduledTaskError`. The new `scheduledTaskNotReady` event (`ScheduledTaskEvents.ScheduledTaskNotReady`) reports it, and `ScheduledTaskHandler#waitForReady()` lets a task wait by hand. `ScheduledTaskHandler#run` takes an optional second argument with the BullMQ job and token. ([#228](https://github.com/wolfstar-project/plugins/pull/228))

## `0.1.0`

### New features

- **New package** — `@wolfstar/plugin-scheduled-tasks` is the counterpart of `@sapphire/plugin-scheduled-tasks` for `@wolfstar/http-framework`. Tasks are `ScheduledTask` pieces run by a BullMQ worker, created with `container.tasks.create()` or repeated on an `interval` or cron `pattern`. It is built on `definePlugin` and `defineModule`: list the package in `modules` in `stars.config`, or pass `scheduledTasks()` to `plugins`. ([#177](https://github.com/wolfstar-project/plugins/pull/177))
