Changes to [`@wolfstar/plugin-sharder`](https://github.com/wolfstar-project/plugins/tree/main/packages/plugin-sharder). The plugin spreads gateway shards across processes, cluster workers, worker threads, and machines. For the weekly summary across all packages, see the [changelog overview](/documentation/changelog/index).

## `0.2.1`

### Bug fixes

- **Cluster strategy options** — Fixes `ClusterStrategy` throwing `Array.prototype.some called on null or undefined` when `execArgv` or `args` are not given: only the given options are passed to `cluster.setupPrimary`, so Node keeps its defaults. A strategy throwing in `spawn` is now reported as a `ShardSpawnError` through `shardError` on every attempt, instead of being retried silently. ([#217](https://github.com/wolfstar-project/plugins/pull/217))

## `0.2.0`

### New features

- **`@wolfstar/plugin-sharder/module`** — Adds a `/module` subpath export. List it in `modules` in `stars.config` to add the package to the auto imports. It needs the optional `@wolfstar/kit` peer; the main entrypoint is unchanged. ([#190](https://github.com/wolfstar-project/plugins/pull/190))

## `0.1.1`

### Bug fixes

- **`./register` export** — Adds a no-op `./register` subpath export. The Stars CLI build imports `<name>/register` for every `@wolfstar/plugin-*` dependency of a project, so the package crashed consumers at startup with `ERR_PACKAGE_PATH_NOT_EXPORTED`. The entrypoint is a no-op: the package has no `@wolfstar/http-framework` `Plugin` hook to register. ([#123](https://github.com/wolfstar-project/plugins/pull/123))

## `0.1.0`

### New features

- **New package** — `@wolfstar/plugin-sharder` implements discord.js's sharder RFC ([discordjs/discord.js#8084](https://github.com/discordjs/discord.js/issues/8084)). ([#112](https://github.com/wolfstar-project/plugins/pull/112))
- **`ShardManager`** — Spawns shards as child processes, cluster workers, worker threads, or on other machines through `ShardManagerProxy` (`NetworkStrategy`, over TLS). It lays gateway shards out automatically, paces identifies across every process, and restarts or reshards with rolling spawns. ([#112](https://github.com/wolfstar-project/plugins/pull/112))
- **Crash supervision** — Supervises crashes after Erlang/OTP: intensity, period, and one-for-one, one-for-all, or rest-for-one restarts. ([#112](https://github.com/wolfstar-project/plugins/pull/112))
- **`ShardManagerProxy`** — Serves one manager with failover, or several at once, and routes messages between shards directly, locally or to peer proxies. ([#112](https://github.com/wolfstar-project/plugins/pull/112))
- **`ShardClient`** — The shard's side: statuses, messages, requests with timeouts, abort and partial broadcasts, gateway shard control, and `gatewayOptions` and `identifyThrottler` for [`GatewayClient`](/documentation/changelog/plugins/plugin-gateway). ([#112](https://github.com/wolfstar-project/plugins/pull/112))
- **`try*` twins** — Every fallible operation has a `try*` twin returning a `Result<T, E>` from `@sapphire/result`, and request handlers may return one. ([#112](https://github.com/wolfstar-project/plugins/pull/112))
- **Message handlers and transformers** — Messages go through named, registrable handlers (JSON, V8, raw) and transformers (gzip, Brotli). ([#112](https://github.com/wolfstar-project/plugins/pull/112))
