Changes to [`@wolfstar/plugin-sharder`](https://github.com/wolfstar-project/plugins/tree/main/packages/plugin-sharder). The plugin spreads gateway shards across processes, cluster workers, worker threads, and machines. For the weekly summary across all packages, see the [changelog overview](/documentation/changelog/index).

## `0.2.1` (2026-10-06)

### Updates

- **Spawn errors are reported** — When a strategy throws in `spawn`, you now get a `ShardSpawnError` (carrying the cause) through `shardError` on every attempt, instead of a silent retry. ([#217](https://github.com/wolfstar-project/plugins/pull/217))

### Bug fixes

- **`ClusterStrategy` without `execArgv` or `args`** — No longer throws `Array.prototype.some called on null or undefined` when you omit `execArgv` or `args`. Only the options you give are passed to `cluster.setupPrimary`, so Node keeps its defaults.

## `0.2.0` (2026-10-05)

### New features

- **`/module` entrypoint** — Adds `@wolfstar/plugin-sharder/module`. List it in `modules` in `stars.config` to add the package to the auto imports. It needs the optional `@wolfstar/kit` peer. The main entrypoint is unchanged. ([#190](https://github.com/wolfstar-project/plugins/pull/190))

## `0.1.1`

### Bug fixes

- **`./register` export** — Adds a no-op `./register` subpath export. The Stars CLI build imports `<name>/register` for every `@wolfstar/plugin-*` dependency, so the package crashed consumers at startup with `ERR_PACKAGE_PATH_NOT_EXPORTED`.

## `0.1.0`

### New features

- **New package** — `@wolfstar/plugin-sharder` implements the discord.js sharder RFC ([discordjs/discord.js#8084](https://github.com/discordjs/discord.js/issues/8084)).
- **`ShardManager`** — Spawns shards as child processes, cluster workers, worker threads, or on other machines through `ShardManagerProxy` (`NetworkStrategy`, over TLS). It lays gateway shards out automatically, paces identifies across every process, and restarts or reshards with rolling spawns.
- **Crash supervision** — Supervises crashes after Erlang/OTP: intensity, period, and one-for-one, one-for-all, or rest-for-one restarts.
- **`ShardManagerProxy`** — Serves one manager with failover, or several at once, and routes messages between shards directly, locally or to peer proxies.
- **`ShardClient`** — The shard's side: statuses, messages, requests with timeouts, abort and partial broadcasts, gateway shard control, and `gatewayOptions` and `identifyThrottler` for [`GatewayClient`](/documentation/changelog/plugins/plugin-gateway).
- **`try*` twins** — Every fallible operation has a `try*` twin returning a `Result<T, E>` from `@sapphire/result`, and request handlers may return one.
- **Message handlers and transformers** — Messages go through named, registrable handlers (JSON, V8, raw) and transformers (gzip, Brotli).
