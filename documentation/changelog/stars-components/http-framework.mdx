Changes to [`@wolfstar/http-framework`](/documentation/packages/http-framework). For the weekly summary across all packages, see the [changelog overview](/documentation/changelog/index).

## `6.3.0` (2026-10-08)

### New features

- **Preconditions** — You can now run checks before a command, its autocomplete, or an interaction handler, following `@sapphire/framework`. Add a `Precondition` piece to the new `preconditions` store and implement `chatInputRun`, `contextMenuRun`, `autocompleteRun`, and/or `interactionHandlerRun`, returning `ok()` or `error()` (a `PreconditionError` for the piece). A piece with a `position` is global and runs in ascending order of it. There are no built-in preconditions. ([#300](https://github.com/wolfstar-project/stars-components/pull/300))
- **`preconditions` option** — List the preconditions to run in `Command.Options` or `InteractionHandler.Options`: by name, by name with a `context`, or as a `PreconditionFunction`. The list is an `AND`, a nested array is an `OR`, and nesting alternates from there, for example `['Connect', ['Moderator', ['DJ', 'SongAuthor']]]`. Pass `{ entries, mode: PreconditionRunMode.Parallel }` to start every entry at once.
- **Precondition events** — The first denial skips the method and emits `chatInputCommandDenied`, `contextMenuCommandDenied`, `autocompleteDenied`, or `interactionHandlerDenied`. New events `preChatInputCommandRun`, `preContextMenuCommandRun`, `chatInputCommandAccepted`, `contextMenuCommandAccepted`, `autocompleteAccepted`, and `interactionHandlerAccepted` let you observe the flow. A piece with no method for a chat input or context menu command denies it; for an autocomplete or an interaction handler it is skipped.
- **New exports** — `AllFlowsPrecondition`, `PreconditionStore`, `runPreconditions`, `PreconditionRunMode`, `PreconditionRunCondition`, the array types, and the related types are exported. `Identifiers` gains `PreconditionMissingChatInputHandler` and `PreconditionMissingContextMenuHandler`.
- **`isUserError`** — A new helper checks whether an error is a `UserError`, and also recognizes a `UserError` from another copy of the package by its shape. ([#298](https://github.com/wolfstar-project/stars-components/pull/298))

### Updates

- **`UserError` routed to `*Denied` events** — A `UserError` thrown by a command, an autocomplete handler, or an interaction handler now goes to `chatInputCommandDenied` / `contextMenuCommandDenied` (`Events.ChatInputCommandDenied`, `Events.ContextMenuCommandDenied`), `autocompleteDenied`, or `interactionHandlerDenied` with `(error: UserError, context)`, instead of `commandError`, `autocompleteError`, or `interactionHandlerError`. Other errors still reach the `*Error` events; the `error` event and the HTTP response are unchanged. ([#298](https://github.com/wolfstar-project/stars-components/pull/298))
- **Run events emitted after preconditions** — `commandRun`, `autocompleteRun`, and `interactionHandlerRun` now fire only after the preconditions pass, so a denied interaction does not emit them. Without preconditions nothing changes.
- **Dependencies** — Updated `@wolfstar/cli` to `2.6.1`.

### Migration

- **Move `UserError` replies to `*Denied` listeners** — If a listener on `commandError`, `autocompleteError`, or `interactionHandlerError` replies to the user with a `UserError` (including the `PreconditionError` from [`@wolfstar/decorators`](/documentation/changelog/stars-components/decorators)), move that logic to `chatInputCommandDenied`, `contextMenuCommandDenied`, `autocompleteDenied`, or `interactionHandlerDenied`. Those errors no longer reach the `*Error` events.

## `6.2.0` (2026-10-06)

### New features

- **Typed command options with `stars codegen`** — Set `codegen.commands` in `stars.config` (`true`, or `{ output }`, default `src/@types/commands.d.ts`) and `stars codegen` reads the commands from the built bot and writes a `CommandOptionsRegistry` entry per command path (`'ping'`, `'math add'`, `'subscriptions twitch add'`). Use `Command.OptionsOf<'math add'>` instead of a hand-written `interface Options`: `required` options are non-optional, `choices` become a literal union, and `channel_types` narrow the channel. `stars codegen --check` fails with `CODEGEN_OUTDATED` when the file is stale, and `--json` reports the result. ([#275](https://github.com/wolfstar-project/stars-components/pull/275))

### Updates

- **Dependencies** — Updated `@wolfstar/cli` to `2.4.0`, `@wolfstar/schema` to `0.7.0`.

## `6.1.1` (2026-10-04)

### New features

- **`stars commands diff` and `stars commands deploy`** — `stars commands diff` compares the commands your built bot defines with those deployed on Discord (`--check` for CI); `stars commands deploy` overwrites them after a confirmation (`--yes` for scripts). Both need `@wolfstar/http-framework` 6.1 or later and a built project. ([#257](https://github.com/wolfstar-project/stars-components/pull/257))
- **`stars doctor`** — Checks the runtime, the framework, credentials, the dev port, the tunnel, and generated files, with a fix for each problem (`--online` also queries Discord, `--json` for scripts).
- **`stars completions <bash|zsh|fish>`** — Prints a shell completion script for the registered commands.

### Updates

- **`stars info`** — Lists the installed modules and the new `dev` options. The README now documents the `dev` options of `stars.config`.
- **Dependencies** — Updated `@wolfstar/cli` to `2.3.0`, `@wolfstar/schema` to `0.6.0`.

## `6.1.0` (2026-10-02)

### New features

- **Object-based plugins** — Define Vite-style plugins with `definePlugin` and the `StarsPlugin` type (`name`, `enforce: 'pre' | 'post'`, `apply`, and the five lifecycle hooks as `(client, options) => …`). Add per-client plugins with the new `plugins` option in `ClientOptions`. A failing hook throws `PluginHookError`, which names the plugin. ([#246](https://github.com/wolfstar-project/stars-components/pull/246))

### Updates

- **Plugin ordering** — `PluginManager` runs hooks as `pre`, plain, then `post`, in registration order within each group. `Client.use` accepts plugin objects and nested arrays.
- **Legacy plugins deprecated** — The `Plugin` class, symbol hooks, and `registerXHook` keep working through an adapter but emit a one-time `DeprecationWarning` (`HTTP_FRAMEWORK_LEGACY_PLUGIN`) per plugin.
- **Dependencies** — Updated `@wolfstar/schema` to `0.5.0`, `@wolfstar/cli` to `2.2.0`.

## 2026-09-24 — `5.0.0`

### New features

- **`Client.fetch()`** — `client.fetch(request)` is the Web `Request`/`Response` counterpart of `listen()`. It runs the same signature verification and routing without binding a port, for Workers, `Bun.serve`, `Deno.serve`, and similar runtimes.
- **`stars` binary ships with `http-framework`** — Installing `@wolfstar/http-framework` now gives you the `stars` command, with no separate `@wolfstar/cli` install.

### Updates

- **Config schema moved to `@wolfstar/schema`** — The `stars.config.*` schema and loader now live in [`@wolfstar/schema`](/documentation/changelog/stars-components/schema). Imports from `@wolfstar/http-framework/config` keep working unchanged.
- **Plugin support** — [`@wolfstar/plugin-api`](/documentation/changelog/plugins/plugin-api), [`@wolfstar/plugin-i18next`](/documentation/changelog/plugins/plugin-i18next), [`@wolfstar/plugin-logger`](/documentation/changelog/plugins/plugin-logger), and [`@wolfstar/plugin-subcommands-advanced`](/documentation/changelog/plugins/plugin-subcommands-advanced) now target `5.x`.

## 2026-09-17 — `4.0.x`

### New features

- **Compatibility version 4 by default** — Convention-first `stars` workflow: `stars dev` forces development mode, `src/locales` is copied and watched automatically, and environment files are discovered under both `src/` and the project root.

### Updates

- **Structured logging** — Leveled logging replaces raw `console` calls for HMR events and command-router warnings.
