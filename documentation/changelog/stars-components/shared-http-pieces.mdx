## `2.0.0`

### Updates

- **Adopt i18next v25 native TypeScript types** — `@wolfstar/shared-http-pieces` removes the hand-maintained `LanguageKeys` export in favor of the generated `CustomTypeOptions` augmentation and direct `TFunction<'commands/shared'>` usage. Adds `@wolfstar/i18next-type-generator`, the CLI used to generate that augmentation from locale JSON files. ([#30](https://github.com/wolfstar-project/stars-components/pull/30))
- **Migrate to `@wolfstar/plugin-i18next`** — Importing `@wolfstar/shared-http-pieces/register` now registers bundled locales automatically via a `preGenericsInitialization` hook that splices `localesPath` into your `Client`'s `i18n.backend.paths` before `@wolfstar/plugin-i18next` builds its handler. No consumer changes are required as long as the register entrypoint is imported before `new Client(...)`. ([#144](https://github.com/wolfstar-project/stars-components/pull/144))
- **Typechecker switch** — `typecheck` scripts now run `golar tsc` instead of `tsc` directly. This is a dev-tooling-only change with no effect on published output. ([#151](https://github.com/wolfstar-project/stars-components/pull/151))

### Updates

- **Dependencies** — Updated `@wolfstar/env-utilities` to `2.0.8` and `@wolfstar/http-framework` to `3.2.1`.

### Migration

- The `T`, `FT`, `resolveKey`, and `resolveUserKey` APIs from `@wolfstar/http-framework-i18n` are deprecated. Use the i18next v25 native `getT` / `getSupportedLanguageT` helpers instead.
