## `0.4.0` (2026-10-02)

### New features

- **Stars modules** — Add `modules` to `stars.config` as a list of package names or `[name, options]` tuples. The CLI installs them with `@wolfstar/kit`'s `setupModules` before the `config:resolved` hook, and the resolved configuration gains `modules` and `runtime` (the runtime plugins and auto-import presets the modules contribute). Runtime plugins are registered in your bot before the legacy `/register` imports, which skip packages listed in `modules`. With the `tsc` and `none` build tools, `stars dev` preloads them with `node --import`, and `stars prepare` writes `.stars/modules.mjs` for production. `stars build`, `stars prepare`, and `stars info` warn with `MODULES_PRELOAD_REQUIRED` when you need that preload. A failing module is reported as a `MODULE_FAILED` diagnostic (exit code 2). See [`@wolfstar/kit`](/documentation/packages/kit). [#247](https://github.com/wolfstar-project/stars-components/pull/247)

### Updates

- **Dependencies** — Updated `@wolfstar/schema` to `0.5.0`.

## `0.3.0`

### New features

- **`env` in `stars.config`** — Added a top-level `env` option that mirrors the setup options from `@wolfstar/env-utilities`. When present, the built entry automatically imports it first, before plugin registrations and the bot's own modules.
- **Lifecycle hooks** — Added Nuxt-style hooks (`config:resolved`, `env:options`, `prepare:*`, `builder:created`, `tsdown:options`, `build:*`, `dev:*`) powered by `hookable`.

### Migration

- `future.compatibilityVersion: 5` is now the default. It is version 4 plus the automatic `env` registration, which activates when the project depends on `@wolfstar/env-utilities` and stays off with Nitro. Version 4 is still supported. Version 3 is end of life: it still works but now reports a `COMPATIBILITY_VERSION_EOL` warning and will be removed in the next major.
- Projects generated by `@wolfstar/create-http-framework` with the `tsdown` or `vite` build no longer call `setup()` from `@wolfstar/env-utilities` by hand. `tsc` and JavaScript projects keep it and set `env: false` ([#243](https://github.com/wolfstar-project/stars-components/pull/243)).

- **Dependencies** — Updated `@wolfstar/schema` to `0.4.0`.
