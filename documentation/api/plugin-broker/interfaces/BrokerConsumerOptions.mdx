### claimIdle?

<ApiMember kind="property" badges={['optional']} signature={['claimIdle?: number']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/775d46b1424d1408340cd641b136e181dbcf011c/packages/plugin-broker/src/BrokerConsumer.ts#L60', label: 'packages/plugin-broker/src/BrokerConsumer.ts:60' }}>

Claims (`XAUTOCLAIM`) the entries any consumer of the group left pending for longer than this many milliseconds,
e.g. one that crashed and never restarted under the same name, and handles them as redeliveries. Checked at most
once per this interval. Left unset, only this consumer's own pending entries are redelivered, when it starts.

This consumer's own entries are claimed too, so an entry whose listener threw is retried in-process once it has
been idle for this long, rather than only on the next start.

An entry's idle time runs from its last delivery, not from its last sign of life: an entry whose listeners are
still running after this long can be claimed and handled again, concurrently, by another consumer. Set it well
above the slowest listener's run time, not just above how fast a crash should be noticed.

</ApiMember>

### consumer

<ApiMember kind="property" signature={['consumer: string']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/775d46b1424d1408340cd641b136e181dbcf011c/packages/plugin-broker/src/BrokerConsumer.ts#L28', label: 'packages/plugin-broker/src/BrokerConsumer.ts:28' }}>

### deadLetterStream?

<ApiMember kind="property" badges={['optional']} signature={['deadLetterStream?: string']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/775d46b1424d1408340cd641b136e181dbcf011c/packages/plugin-broker/src/BrokerConsumer.ts#L77', label: 'packages/plugin-broker/src/BrokerConsumer.ts:77' }}>

The Redis key of the stream the entries exceeding [BrokerConsumerOptions.maxDeliveries](/documentation/api/plugin-broker/interfaces/BrokerConsumerOptions#maxdeliveries) are moved to. Each
dead-lettered entry keeps its `event` and `payload` fields, plus the original `id`, `stream`, `group`,
`consumer`, and `deliveries`.

**Default:** `${stream}:dead`

</ApiMember>

### maxDeliveries?

<ApiMember kind="property" badges={['optional']} signature={['maxDeliveries?: number']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/775d46b1424d1408340cd641b136e181dbcf011c/packages/plugin-broker/src/BrokerConsumer.ts#L69', label: 'packages/plugin-broker/src/BrokerConsumer.ts:69' }}>

The number of times an entry can be delivered: past it, the entry is moved to
[BrokerConsumerOptions.deadLetterStream](/documentation/api/plugin-broker/interfaces/BrokerConsumerOptions#deadletterstream) instead of being handed to the listeners again. Left unset, a
failing entry is retried forever.

Deliveries are counted by Redis (the `XPENDING` delivery counter), so they add up across consumers and restarts.

</ApiMember>

### shutdownSignals?

<ApiMember kind="property" badges={['optional']} signature={['shutdownSignals?: readonly Signals[]']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/775d46b1424d1408340cd641b136e181dbcf011c/packages/plugin-broker/src/BrokerConsumer.ts#L88', label: 'packages/plugin-broker/src/BrokerConsumer.ts:88' }}>

The process signals that stop the consumer (see [BrokerConsumer.stop](/documentation/api/plugin-broker/classes/BrokerConsumer#stop)) while it runs. Once it has stopped,
the signal is raised again if nothing else listens to it, so the process still terminates as it would have
without this option; otherwise, exiting is left to those other listeners.

**Example**

```typescript
shutdownSignals: ['SIGTERM', 'SIGINT'];
```

</ApiMember>
