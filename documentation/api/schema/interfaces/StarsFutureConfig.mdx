Nuxt-style compatibility block. New projects need not set it; version 4 stays available, and version 3 is kept only
as an end-of-life migration escape hatch for projects that still use a standalone `tsdown.config.*`.

## Properties

### compatibilityVersion?

<ApiMember kind="property" badges={['optional']} signature={['compatibilityVersion?: ', ['StarsCompatibilityVersion', '/documentation/api/schema/type-aliases/StarsCompatibilityVersion']]} source={{ url: 'https://github.com/wolfstar-project/stars-components/blob/3785ac54e2c681b0525fad9f298b406992acafd5/packages/schema/src/types/config.ts#L133', label: 'packages/schema/src/types/config.ts:133' }}>

The major whose defaults apply.

`7` (opt-in, not the default): everything in `6`, plus the configuration decides what registers. A
`@wolfstar/plugin-*` dependency is no longer activated by its name (no `import "<name>/register"` is injected into
the entry): only the packages in `modules`, and the ones they install, are. A plugin that is not a module must be
imported by the bot itself. `stars info`/`stars doctor` and the build report an installed plugin that is left out.

`6` is the default: everything in `5`, plus the generated TypeScript configuration split in two, the way a Nuxt 4
project has it. `stars prepare` writes `.stars/tsconfig.app.json` (the bot sources) and
`.stars/tsconfig.node.json` (`stars.config.*`, `vitest.config.*`, `scripts/**`, ...) instead of a single
`.stars/tsconfig.json`, and the project's own `tsconfig.json` becomes a solution-style file that only references
them. The `tsdown` build uses the app config, and `stars typecheck` checks both. `5` and `4` keep the single
`.stars/tsconfig.json` and the `extends` a project's `tsconfig.json` already has, byte for byte.

`5`: everything in `4`, plus `env` registered automatically in the built entry
(see [StarsConfig.env](/documentation/api/schema/interfaces/StarsConfig#env)) when the project depends on `@wolfstar/env-utilities`.

`4`:

- auto imports are on by default with the `tsdown` build tool ([StarsImportsConfig](/documentation/api/schema/interfaces/StarsImportsConfig)), and the
  `autoImports()` plugin is wired into the build by `stars` itself.
- `tsdown` is configured from [StarsConfig.tsdown](/documentation/api/schema/interfaces/StarsConfig#tsdown) only. A `tsdown.config.*` in the project root is
  rejected rather than silently ignored, so a build never loses the plugins it declares.
- `build.tool: 'auto'` resolves to `tsdown` for any TypeScript entry, without looking for a `tsdown.config.*`
  or a `tsdown` dependency first.
- `env` is opt-in.

`3` (**end-of-life**) keeps the legacy behaviour: auto imports off unless asked for, and a `tsdown.config.*`
loaded and merged with [StarsConfig.tsdown](/documentation/api/schema/interfaces/StarsConfig#tsdown). It prints a warning and is removed in the next major.

**Default**

```ts
6;
```
