### cache?

<ApiMember kind="property" badges={['optional']} signature={['cache?: ', ['Cache', '/documentation/api/plugin-cache/interfaces/Cache'], ' | null']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L187', label: 'packages/plugin-gateway/src/GatewayClient.ts:187' }}>

A `@wolfstar/plugin-cache` cache (in memory or Redis) whose raw stores back the managers, instead of the
in-memory caches of instances built by [GatewayClientOptions.cacheConstructor](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cacheconstructor): structures are then built
on every read. `null` disables caching: the managers' `cache.get` always answer `undefined`, update events
receive `null` as their previous state, and `fetch` always hits the API.

Every entity cache is optional: an entity kind the cache does not hold is simply not cached, see
`createInMemoryCache`'s `entities` option.

**Default**

```ts
undefined;
```

</ApiMember>

### cacheConstructor?

<ApiMember kind="property" badges={['optional']} signature={['cacheConstructor?: ', ['CacheConstructor', '/documentation/api/plugin-gateway/type-aliases/CacheConstructor']]} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L125', label: 'packages/plugin-gateway/src/GatewayClient.ts:125' }}>

Builds the cache of each entity, the one its managers expose as `manager.cache`: the `cacheConstructor` of the
discord.js RFC #11426. The caches hold structure instances, which dispatches patch in place.

The class is instantiated once per entity with `(creator, name, options)`, see [CacheConstructor](/documentation/api/plugin-gateway/type-aliases/CacheConstructor):
`options` carries `keyOf`, the key of raw data, which `add` must use since most entities are not keyed by their
`id`, `refresh`, to call on what `get` and `add` hand out so that relations are resolved again, and the entity's
[GatewayClientOptions.cacheOptions](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cacheoptions). Extending [CollectionCache](/documentation/api/plugin-gateway/classes/CollectionCache) is the recommended way.

A cache that is not a `Map` cannot be enumerated: the dispatch cascades (`GUILD_DELETE`, `CHANNEL_DELETE`), the
reconciliation on `READY`, the emoji and sticker diff events, and `listCached` do not work with it.

It cannot be combined with [GatewayClientOptions.cache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cache) or [GatewayClientOptions.makeCache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#makecache), which
back the managers with raw `@wolfstar/plugin-cache` stores instead: passing both throws. `cache: null` wins over
it: nothing is cached, and the class is never instantiated.

The structures of a cache of instances are built synchronously, so the caches their relations are read from
must be synchronous too.

**Default**

```ts
CollectionCache;
```

</ApiMember>

### cacheErrors?

<ApiMember kind="property" badges={['optional']} signature={['cacheErrors?: "miss" | "throw"']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L239', label: 'packages/plugin-gateway/src/GatewayClient.ts:239' }}>

What the managers do when a cache read or write fails, e.g. while Redis is unreachable. A `cacheError` event is
emitted either way.

- `"miss"`: treat it as a cache miss, falling back to the API or to the data at hand.
- `"throw"`: reject with the error.

Dispatches follow [GatewayClientOptions.cacheFailure](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cachefailure) instead.

**Default**

```ts
'miss';
```

</ApiMember>

### cacheFailure?

<ApiMember kind="property" badges={['optional']} signature={['cacheFailure?: "skip" | "emitUncached"']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L277', label: 'packages/plugin-gateway/src/GatewayClient.ts:277' }}>

What to do with a dispatch whose cache read or write fails, e.g. while Redis is unreachable. The error is always
reported through the `error` event (or the logger when nobody listens to it).

- `"skip"`: drop the dispatch's event, so listeners never see state the cache does not hold.
- `"emitUncached"`: still emit the event, built from the payload alone, with `null` as the previous state.

**Default**

```ts
'skip';
```

</ApiMember>

### cacheOptions?

<ApiMember kind="property" badges={['optional']} signature={['cacheOptions?: ', ['Partial', 'https://www.typescriptlang.org/docs/handbook/utility-types.html#partialtype'], '<', ['Record', 'https://www.typescriptlang.org/docs/handbook/utility-types.html#recordtype'], '<keyof ', ['CacheEntityTypes', '/documentation/api/plugin-cache/interfaces/CacheEntityTypes'], ', ', ['CacheEntityOptions', '/documentation/api/plugin-gateway/interfaces/CacheEntityOptions'], '>>']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L150', label: 'packages/plugin-gateway/src/GatewayClient.ts:150' }}>

The options of the cache of each entity, passed to [GatewayClientOptions.cacheConstructor](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cacheconstructor) (the default
`CollectionCache` included) next to `keyOf` and `refresh`. `maxSize` bounds the amount of entries of an entity,
the oldest one being evicted first.

By default every received entity stays in memory until a dispatch removes it: this is what bounds it, next to
[GatewayClientOptions.policies](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#policies) and `cache: null`.

It only applies to caches built by a constructor. Like `cacheConstructor`, it cannot be combined with
[GatewayClientOptions.cache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cache) or [GatewayClientOptions.makeCache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#makecache), whose stores have their own
bounds: passing both throws. With `cache: null` it is ignored.

**Default**

```ts
undefined;
```

**Example**

```typescript
// Keep the 1000 most recent messages, and no presence.
const client = new GatewayClient({
	intents,
	cacheOptions: { messages: { maxSize: 1_000 }, presences: { maxSize: 0 } }
});
```

</ApiMember>

### makeCache?

<ApiMember kind="property" badges={['optional']} signature={['makeCache?: ', ['CacheFactory', '/documentation/api/plugin-cache/type-aliases/CacheFactory']]} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L207', label: 'packages/plugin-gateway/src/GatewayClient.ts:207' }}>

Creates the raw `@wolfstar/plugin-cache` store of each entity kind, `null` or `undefined` not to cache it. Called
once per entity kind when the client is constructed, and takes precedence over
[GatewayClientOptions.cache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cache). Not to be confused with [GatewayClientOptions.cacheConstructor](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cacheconstructor), which
builds caches of structure instances.

**Default**

```ts
undefined;
```

**Example**

```typescript
import { MemoryEntityCache } from '@wolfstar/plugin-cache';

// Cache guilds, channels, and roles only.
const client = new GatewayClient({
	intents,
	makeCache: (entity) => (['guilds', 'channels', 'roles'].includes(entity) ? new MemoryEntityCache() : null)
});
```

</ApiMember>

### policies?

<ApiMember kind="property" badges={['optional']} signature={['policies?: ', ['CachePolicies', '/documentation/api/plugin-cache/type-aliases/CachePolicies']]} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L226', label: 'packages/plugin-gateway/src/GatewayClient.ts:226' }}>

The policies deciding which entries get cached, and for how long, per entity kind, see `withPolicy`. They apply to
every write, from dispatches as well as from the managers: an entry its `filter` rejects is not cached, and the
entry already cached under its key is deleted.

`ttl` only applies to `@wolfstar/plugin-cache` stores ([GatewayClientOptions.cache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cache),
[GatewayClientOptions.makeCache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#makecache)): the caches of instances built by
[GatewayClientOptions.cacheConstructor](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cacheconstructor), the default included, have no per-entry time-to-live.

**Default**

```ts
undefined;
```

**Example**

```typescript
// Do not cache bots, and forget messages after an hour.
policies: { users: { filter: (user) => !user.bot }, messages: { ttl: () => 3_600_000 } }
```

</ApiMember>

### sessionStore?

<ApiMember kind="property" badges={['optional']} signature={['sessionStore?: ', ['GatewaySessionStore', '/documentation/api/plugin-cache/interfaces/GatewaySessionStore']]} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L260', label: 'packages/plugin-gateway/src/GatewayClient.ts:260' }}>

Where to keep the shards' sessions, e.g. `createRedisSessionStore` from `@wolfstar/plugin-cache`, so a restarted
process resumes them instead of identifying again: no identify quota spent, the dispatches missed meanwhile
replayed, and no `GUILD_CREATE` burst. Pair it with a persistent cache, since a resumed session does not refill an
empty one. Use [GatewayClient.destroy](/documentation/api/plugin-gateway/classes/GatewayClient#destroy)'s `resumable` option to keep the sessions on a graceful shutdown.

The store is read once per shard when it first connects, then mirrored in memory, and written in the background
on every sequence change, see [GatewayClientOptions.sessionStoreTimeout](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#sessionstoretimeout). Its failures are reported as
`GatewaySessionStoreError`s through the `error` event and never stop a shard: a failed read identifies.

It replaces `gateway.retrieveSessionInfo` and `gateway.updateSessionInfo`, passing either alongside it throws.

**Default**

```ts
undefined;
```

</ApiMember>

### sweepers?

<ApiMember kind="property" badges={['optional']} signature={['sweepers?: ', ['SweeperOptions', '/documentation/api/plugin-gateway/type-aliases/SweeperOptions']]} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L174', label: 'packages/plugin-gateway/src/GatewayClient.ts:174' }}>

Evicts entries from the caches of instances on a schedule, like discord.js's `sweepers` option: each entity has
its own sweeper, evicting what a `filter` selects or what outlived a `lifetime`, every `interval` seconds. See
[Sweepers](/documentation/api/plugin-gateway/classes/Sweepers), whose methods sweep on demand, and [DefaultSweeperSettings](/documentation/api/plugin-gateway/variables/DefaultSweeperSettings).

The timers do not keep the process alive, and stop on [GatewayClient.destroy](/documentation/api/plugin-gateway/classes/GatewayClient#destroy). A sweep that throws (e.g. a
filter) is reported through `cacheError`, and the next one runs as scheduled.

It only applies to caches built by a constructor, the default included: like `cacheConstructor`, combining it with
[GatewayClientOptions.cache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#cache) or [GatewayClientOptions.makeCache](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#makecache) throws, their stores expire entries
with the `ttl` of [GatewayClientOptions.policies](/documentation/api/plugin-gateway/interfaces/GatewayClientOptions#policies). With `cache: null` it is ignored.

**Default**

```ts
undefined;
```

**Example**

```typescript
sweepers: {
  messages: { interval: 3_600, lifetime: 1_800 },
  users: { interval: 3_600, filter: () => (user) => user.bot },
}
```

</ApiMember>

### waitGuildTimeout?

<ApiMember kind="property" badges={['optional']} signature={['waitGuildTimeout?: number']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/e92aba58265993929cc64df3a7c9948a05850e13/packages/plugin-gateway/src/GatewayClient.ts#L305', label: 'packages/plugin-gateway/src/GatewayClient.ts:305' }}>

How long, in milliseconds, the client waits for every guild `READY` listed as initially unavailable to become
available (its `GUILD_CREATE`) before emitting `clientReady` anyway, like discord.js's `waitGuildTimeout`.

It only bounds the wait on guild availability: `clientReady` still never fires before every shard this client
manages has connected, however long that takes, even past this timeout.

Skipped (waits `0` ms) when `intents` does not include `GatewayIntentBits.Guilds`, since without it Discord never
sends the guilds' data, so no `GUILD_CREATE` for them ever arrives.

**Default**

```ts
15_000;
```

</ApiMember>
