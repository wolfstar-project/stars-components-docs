Manages the [Role](/documentation/api/plugin-gateway/classes/Role)s known to the client.

`guild.roles` (or `client.guilds.roles(guildId)`) is this manager built for one guild, like discord.js's:
`cache` takes the role's ID alone, and the methods lose their `guildId` argument.

### cache

<ApiMember kind="property" badges={['readonly']} signature={['readonly cache: ', ['Cache', '/documentation/api/plugin-gateway/interfaces/Cache'], '<', ['Role', '/documentation/api/plugin-gateway/classes/Role'], '<"">>']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/5bb3b6c632bbc7d73534213f6634e9fd02ee1c15/packages/plugin-gateway/src/managers/CachedManager.ts#L142', label: 'packages/plugin-gateway/src/managers/CachedManager.ts:142' }} inheritedFrom={[['CachedManager.cache', '/documentation/api/plugin-gateway/classes/CachedManager#cache']]}>

The cache of this manager's entity.

On a manager built for one guild (`guild.members`), it is the client's cache taking the ID of the entity alone.
`get`, `has`, `set` and `delete` cost the same as on the client's; `getSize` and `clear` scan the keys of every
guild to find the ones of this guild, unlike discord.js's per-guild collections: avoid calling them for every
guild in a loop.

**Example**

```typescript
const user = await client.users.cache.get(userId);
```

</ApiMember>
