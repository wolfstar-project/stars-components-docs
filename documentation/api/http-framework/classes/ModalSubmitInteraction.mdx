### fields

<ApiMember kind="accessor" signature={['get fields(): ', ['ModalInteractionOptionResolver', '/documentation/api/http-framework-utilities/classes/ModalInteractionOptionResolver']]} source={{ url: 'https://github.com/wolfstar-project/stars-components/blob/097d6480525cd5b8794598a8168af3b359bc481e/packages/http-framework/src/lib/interactions/structures/interactions/ModalSubmitInteraction.ts#L42', label: 'packages/http-framework/src/lib/interactions/structures/interactions/ModalSubmitInteraction.ts:42' }}>

Typed access to the submitted fields, found by the custom ID of their component.

It reads text inputs, string, user, role, channel and mentionable selects, the members behind a user select, and
uploaded files, whether they sit in an action row or in a label. Other components, such as radio and checkbox
groups, are only reachable through `fields.get(customId)`, which returns the raw component. The resolver is built
on first access and reused after that.

The getters throw when the component is missing or of another type, and the select getters throw a
`TypeError` when the payload has no `resolved` data (or no `members`, in a DM), as the resolver in
`@wolfstar/discord-utilities` does.

**Example**

```typescript
const reason = interaction.fields.getTextInput('reason');
const roles = interaction.fields.getSelectedRoles('roles');
```

**See also**

- [ModalSubmitInteraction.data](/documentation/api/http-framework/classes/ModalSubmitInteraction#data-1) for the raw data.

</ApiMember>
