This class is the root of every framework-thrown error, allowing consumers to distinguish
errors that are meant to be shown to the user from unexpected, internal ones.

When a command, an autocomplete handler, or an interaction handler throws a `UserError` (or any subclass), the
client emits the matching `*Denied` event ([Events.ChatInputCommandDenied](/documentation/api/http-framework/enumerations/Events#member-chatinputcommanddenied), [Events.ContextMenuCommandDenied](/documentation/api/http-framework/enumerations/Events#member-contextmenucommanddenied),
[Events.AutocompleteDenied](/documentation/api/http-framework/enumerations/Events#member-autocompletedenied), or [Events.InteractionHandlerDenied](/documentation/api/http-framework/enumerations/Events#member-interactionhandlerdenied)) instead of the `*Error` one, so listeners
can reply to the user without reporting an expected failure as a bug. Use [isUserError](/documentation/api/http-framework/functions/isUserError) to apply the same check.

**Example**

```typescript
throw new UserError({
	identifier: Identifiers.ArgumentIntegerTooSmall,
	message: 'The number you provided is too small.',
	context: { received: 2, minimum: 3 }
});
```
