Spawns shards, keeps them alive, and carries messages between them.

<ApiSignature
	tokens={[
		'class ShardManager extends EventEmitter<',
		['ShardManagerEvents', '/documentation/api/plugin-sharder/interfaces/ShardManagerEvents'],
		'>'
	]}
/>

<ApiHierarchy extends={[['EventEmitter<', ['ShardManagerEvents', '/documentation/api/plugin-sharder/interfaces/ShardManagerEvents'], '>']]} />

Follows discord.js's sharder RFC (discordjs/discord.js#8084): a "shard" is a process, cluster worker, worker
thread, or remote process, which may connect several gateway shards, and the manager talks to each through a
[ShardChannel](/documentation/api/plugin-sharder/classes/ShardChannel). The manager is agnostic of the bot: a shard runs any script using [ShardClient](/documentation/api/plugin-sharder/classes/ShardClient).

**Example**

```ts
const manager = new ShardManager({ strategy: new ForkStrategy({ path: "./bot.js" }), clusters: 4 });
manager.setRequestHandler((body, { channel }) => ...);
await manager.spawn();
const guilds = await manager.broadcastRequest({ type: "guildCount" });
```

### addDestroyHook()

<ApiMember kind="method" source={{ url: 'https://github.com/wolfstar-project/plugins/blob/5bb3b6c632bbc7d73534213f6634e9fd02ee1c15/packages/plugin-sharder/src/ShardManager.ts#L662', label: 'packages/plugin-sharder/src/ShardManager.ts:662' }}>

<ApiSignature

		'addDestroyHook(hook: ',
		['ShardManagerDestroyHook', '/documentation/api/plugin-sharder/type-aliases/ShardManagerDestroyHook'],
		'): () => void'
	]}
/>

Runs a hook at the end of every [ShardManager.destroy](/documentation/api/plugin-sharder/classes/ShardManager#destroy), once the shards are closed: the place to flush what
is left to export, such as traces, before the manager's process exits.

The hooks run one after the other, in the order they were added, even when closing the shards failed. A hook that
throws is reported through the `error` event (or logged when nothing listens) and does not stop the others. Adding
the same function twice adds it once.
