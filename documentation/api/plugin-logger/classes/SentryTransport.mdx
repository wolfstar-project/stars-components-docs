A [Transport](/documentation/api/plugin-logger/interfaces/Transport) forwarding entries to Sentry. What Sentry receives depends on the entry's
level, from the cheapest signal to the most prominent:

- from [`logLevel`](/documentation/api/plugin-logger/interfaces/SentryTransportOptions#loglevel): a Sentry Log (needs `enableLogs`);
- from [`breadcrumbLevel`](/documentation/api/plugin-logger/interfaces/SentryTransportOptions#breadcrumblevel), below `level`: a
  breadcrumb attached to the next issue;
- from [`level`](/documentation/api/plugin-logger/interfaces/SentryTransportOptions#level) (default `error`): an issue, so an
  application's issue stream is not flooded with lifecycle logs.

Logs and breadcrumbs are off unless asked for. Sentry's default console integration already
records breadcrumbs for `console.*`, so enabling them next to a [ConsoleTransport](/documentation/api/plugin-logger/classes/ConsoleTransport) would
duplicate them.

The Sentry client is injected rather than imported, exactly like `WinstonTransport` takes a
winston instance: this keeps `@wolfstar/plugin-logger` free of a runtime dependency on any Sentry
SDK, so it works with `@sentry/node`, `@sentry/bun` and the like alike.

**Example**

```ts
import * as Sentry from '@sentry/node';
import { SentryTransport } from '@wolfstar/plugin-logger';

const transport = new SentryTransport({ client: Sentry, breadcrumbLevel: LogLevel.Info });
```
