A Map-like, per-entity key-value store, the `Cache` interface of the discord.js RFC #11426.

<ApiSignature tokens={['interface EntityCache<Raw>']} />

<ApiHierarchy extendedBy={[[['IterableEntityCache', '/documentation/api/plugin-cache/interfaces/IterableEntityCache']]]} />

<ApiParams title="Type Parameters">

<ApiParam name="Raw" />

</ApiParams>

Every method returns an [Awaitable](/documentation/api/plugin-cache/type-aliases/Awaitable), so synchronous (in-memory) and asynchronous (Redis) stores implement the
exact same contract. Enumerating the entries is an optional extension, see [IterableEntityCache](/documentation/api/plugin-cache/interfaces/IterableEntityCache): a remote
store may not be able to do it cheaply.

## Properties

### synchronous?

<ApiMember kind="property" badges={['readonly', 'optional']} signature={['readonly synchronous?: boolean']} source={{ url: 'https://github.com/wolfstar-project/plugins/blob/775d46b1424d1408340cd641b136e181dbcf011c/packages/plugin-cache/src/lib/types.ts#L133', label: 'packages/plugin-cache/src/lib/types.ts:133' }}>

Whether every method returns its result synchronously, never a promise. Optional: a cache without it is treated
as asynchronous, which is always safe.

An [Awaitable](/documentation/api/plugin-cache/type-aliases/Awaitable) cannot be told apart from a promise without calling the method, so this is how consumers
know they can read the cache without awaiting it, e.g. `@wolfstar/plugin-gateway`'s `cached` accessors.

</ApiMember>
