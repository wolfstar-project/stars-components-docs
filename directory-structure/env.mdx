Bot credentials and configuration variables live in `.env` files. The generated project includes one with Discord credentials, and `@wolfstar/env-utilities` loads layered dotenv files with the most specific value first.

Open the generated `.env` file and provide the credentials from the Discord developer portal:

```dotenv
DISCORD_TOKEN=your_application_token
DISCORD_PUBLIC_KEY=your_application_public_key
```

Never commit this file or expose either value in logs.

With compatibility version 5 (the default), `stars` loads the environment for you. `setup()` from `@wolfstar/env-utilities` is called before plugin registrations and your own modules. Pass options through the `env` option of `stars.config`:

```typescript stars.config.ts
export default defineConfig({
	env: { prefix: 'BOT_', loader: 'varlock' }
});
```

The loader applies environment-specific files in this order:

```text
.env.development.local → .env.local → .env.development → .env
.env.test.local        → .env.test                    → .env
```

`.env.local` is intentionally skipped in the test environment.
