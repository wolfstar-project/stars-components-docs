## `stars codegen`

Runs the code generators that `codegen` in `stars.config` enables and writes their files. Pass `--check` in CI to fail with `CODEGEN_OUTDATED` when a file is stale instead of writing it. Pass `--json` to print `{ check, results }`. Pass `--only i18n` or `--only commands` to run a single generator. Repeat the flag or comma-separate the values to run several (`--only i18n,commands`).

- `codegen.i18n` types the i18next resources with `@wolfstar/i18next-type-generator`. It is on by default when `src/locales/en-US` exists.
- `codegen.commands` types the options of every command from its builder. It is off by default. `true` writes `src/@types/commands.d.ts`, and `{ output }` picks another file, relative to the project root.

```typescript
import { defineConfig } from '@wolfstar/http-framework/config';

export default defineConfig({
	codegen: { commands: true }
});
```

## Typed command options

With `codegen.commands` enabled, the generated file augments `CommandOptionsRegistry` with one entry per command path (`'ping'`, `'math add'`, `'subscriptions twitch add'`):

```typescript
// src/@types/commands.d.ts (generated by `stars codegen`, do not edit)
declare module '@wolfstar/http-framework' {
	interface CommandOptionsRegistry {
		'math add': {
			left: number;
			right: number;
		};
	}
}
```

Handlers type their options with `Command.OptionsOf<'path'>`, so you no longer maintain a hand-written `interface
Options` that can drift from the builder. A renamed option, a flipped `required`, or a changed type stops compiling:

```typescript
public add(interaction: Command.ChatInputInteraction, { left, right }: Command.OptionsOf<'math add'>) {}
```

The generated types follow what the framework resolves at runtime:

- Every option has the shape the handler receives (`user` is `TransformedArguments.User`, `role` is `APIRole`, and so on).
- A `required` option is not optional.
- `choices` become a literal union.
- `channel_types` narrow a channel option.
- A localized command is keyed by its default name, the one the handler receives.
- Context menu commands have no options and are skipped.
- A path registered more than once (a command restricted to several guilds) keeps its first definition.

For an autocomplete handler, `Command.AutocompleteArguments<Command.OptionsOf<'math add'>>` types `focused` from the same entry.

## Build first

`stars codegen` reads the commands from the built bot, the same way `stars commands diff` does, so run `stars build` first. Loops and factories in your builders need no special care, because the types come from what the bot actually registers. The CLI starts the bot in a mode that loads its pieces, reports its registry, and exits before it listens or talks to Discord. It never calls `client.login`.

The bot still runs its own setup, so the values it reads while starting (`DISCORD_CLIENT_ID`, `DISCORD_PUBLIC_KEY`, and so on) must be set. In CI, where the real secrets are not available, pass placeholders:

```sh
stars build
DISCORD_CLIENT_ID=1 DISCORD_TOKEN=x DISCORD_PUBLIC_KEY=0 stars codegen --check
```

## Run one generator in CI

`--only` lets a CI job run the generator it can. The i18n types only read the locale files, so you can check them without the bot's secrets or a build. The command types need the built bot and the values it reads while starting:

```sh
stars codegen --check --only i18n
stars build && DISCORD_CLIENT_ID=1 DISCORD_TOKEN=x DISCORD_PUBLIC_KEY=0 stars codegen --check --only commands
```

For example, a GitHub Actions step that checks the i18next types without any secrets:

```yaml
- name: Check i18n types
  run: pnpm exec stars codegen --check --only i18n
```

A generator named in `--only` must be enabled. `--only commands` with `codegen.commands` off fails with [`CODEGEN_GENERATOR_DISABLED`](/api/errors/cli#codegen_generator_disabled) instead of passing without checking anything. An unknown name fails with [`INVALID_OPTION`](/api/errors/cli#invalid_option).

`stars dev` does not generate command types, and neither does `stars prepare`, which has no build to read from yet. Run `stars codegen` after you change an option, and `stars codegen --check` in CI to keep the file up to date.

See also [`@wolfstar/cli`](/documentation/packages/cli).
